# ФСП Карьера — фронтенд

Монорепозиторий с двумя кабинетами:

- `apps/candidate` — специалист, порт `5173`;
- `apps/employer` — работодатель, порт `5174`;
- `packages/shared` — API-клиент, авторизация, компоненты и стили.

## Дизайн ФСП

В `packages/shared/src/assets` перенесены материалы из `docs/брендбук`: логотип, изображение `face1.png` для кабинета специалиста, карта `map1.png` для кабинета работодателя, графическая линия `lineline1.png` и два начертания JetBrains Mono. `brand.css` содержит фирменные цвета и подключения шрифтов. `styles.css` импортирует его и содержит единые стили компонентов и адаптивной вёрстки. Оба кабинета используют одну дизайн-систему, но имеют разные главные экраны.

## Локальный запуск

### Локальный запуск без входа (PowerShell)

В корне репозитория:

```powershell
if (!(Test-Path .env)) { Copy-Item .env.example .env }
docker compose up -d --build
Invoke-RestMethod http://localhost:8080/actuator/health
```

В каталоге `frontend`:

```powershell
if (!(Test-Path .env.local)) { Copy-Item .env.example .env.local }
npm ci
```

Запустите приложения в двух отдельных терминалах из каталога `frontend`:

```powershell
npm run dev:candidate
```

```powershell
npm run dev:employer
```

Откройте `http://localhost:5173` и `http://localhost:5174`. Оба кабинета открываются сразу: специалист использует `candidate1@example.com`, работодатель — `employer1@example.com`. Демо-пользователя можно сменить в меню профиля.

Перед открытием кабинетов проверьте `http://localhost:8080/actuator/health`: нужен ответ `status: UP`. При недоступном API главные страницы остаются видимыми и показывают предупреждение с кнопкой «Проверить снова». Dev-серверы отдают страницы без кеширования.

Остановить Vite: `Ctrl+C` в обоих терминалах. Остановить backend и базу из корня репозитория: `docker compose down`. Данные базы сохраняются в Docker volume.

## Keycloak, если понадобится позже

Установите в `.env.local`:

```dotenv
VITE_AUTH_MODE=keycloak
VITE_KEYCLOAK_URL=http://localhost:8081
VITE_KEYCLOAK_REALM=jobsearcher
VITE_KEYCLOAK_CLIENT_ID=jobsearcher-frontend
```

Приложения используют Authorization Code + PKCE через `keycloak-js`. Вход выполняется через Keycloak; запросы к API содержат Bearer токен. Роли проверяются ответом `/me`. Для production оба приложения должны получать `/api/v1` через прокси на backend и быть внесены в разрешённые redirect URI / web origins клиента Keycloak.

## Реализованные сценарии

Специалист: профиль, настройки приватности и согласия, публикация, загрузка PDF резюме, достижения ФСП, анкета, тест A/B/C с прокторингом, вакансии и отклики, приглашения и чат.

Работодатель: профиль компании, потребности, объяснимая подборка, банк кандидатов с фильтром ФСП, приглашения с обязательным диапазоном зарплаты, публикация и редактирование вакансий, входящие отклики и чат.

Редактирование вакансий использует добавленный backend метод `PUT /api/v1/vacancies/{id}`. Поле зарплаты проверяется на клиенте и сервере. Контакты кандидата отображаются только после принятия приглашения согласно ответам API.

## Проверки

```bash
npm run typecheck
npm run build
npm run test:proctor
```

`test:proctor` использует установленный Google Chrome и тестовый API: проверяет блокировку меню и смены аккаунта, переходы через hash и историю, отправку нарушения при уходе со страницы и снятие блокировки после завершения. Серверы не запускаются. Для другого Chromium-браузера задайте путь в `PROCTOR_BROWSER_PATH`.

Backend сохраняет ограничения тестирования и приватности; интерфейс сообщает об ошибках API, включая `JS_006`, `JS_007` и `JS_008`. Идеи без API из контракта, в том числе webcam presence, не представлены как работающие функции.
