# Механика тестирования

## Проблема

Единый набор заданий быстро расходится между кандидатами. Генерация «с нуля» нейросетью плохо сопоставима по сложности.

## Решение MVP

1. **Банк параметризованных заданий** (`test_item`) с вариантами формулировок (`variants_json`) и пулом опций.
2. **Уникальная сессия**: `seed = CRC32(candidateId + attemptId)`.
3. На seed: shuffle заданий, выбор variant, shuffle options.
4. Кандидату отдаются только `code/label` опций без флага correct.
5. Оценка MCQ — по эталону; OPEN_TEXT — по rubric keywords (+ опционально LLM).
6. IT: полноценный банк по специализациям/грейдам; другие отрасли — короткий MCQ.

## Грейд

- Порог pass: score ≥ 0.6
- Fail → попытка понизить на один грейд (если есть)
- Pass ≥ 0.9 → опциональное повышение на один грейд
- Смена не чаще 1 раза в 90 дней

## Устойчивость к leak

Даже при публикации ответов «варианта A» другой кандидат получает другой seed/порядок/формулировку. Сопоставимость сохраняется за счёт общего банка и единых эталонов.
